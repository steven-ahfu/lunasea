## Project Overview

LunaSea is a self-hosted controller for a home media-server stack. It covers Sonarr, Radarr, Lidarr,
SABnzbd, NZBGet, Tautulli, Tracearr, Newznab search and Wake-on-LAN. Overseerr exists as a
notification-only source and has a hidden module. The main product is a cross-platform **Flutter app**
for Android, iOS, macOS, Linux, Windows and Web (Wasm). The app talks directly to the user's services
using per-profile connection settings stored locally in **Hive CE**. There is no LunaSea backend for app data.

This repository is a **monorepo fork**. Upstream is JagandeepBrar/lunasea, which was archived at v11.0.0.
Dim145/lunasea forked it, and steven-ahfu/lunasea is this repo. The fork made several changes:
- The version was reset to **1.2.0**.
- The bundle id was renamed to **`app.dim145.lunasea`**.
- **Firebase/FCM was replaced by ntfy**, with a companion **Node/TypeScript notification service**. That
  service turns *arr webhooks into ntfy pushes that deeplink back into the app (`lunasea://<module>?event=...`).
- The docs moved from GitBook to **Jekyll (Just the Docs)**.
- Release-only GitHub Actions now build the platform artifacts plus hardened multi-arch Docker images on GHCR.

## Architecture

```
 ┌─────────────────────── Flutter app (lunasea/) ────────────────────────┐
 │ main → bootstrap (Hive, logger, theme, network, router, cache, links) │
 │ LunaBIOS → MultiProvider(<Module>State…) → MaterialApp.router          │
 │ LunaModule enum ─ metadata/routing/webhook extensions                  │
 │ <Module>Routes (go_router) → routes/<page>/route.dart (Luna* widgets)  │
 │ <Module>State (ChangeNotifier) → api/<svc> (Dio/Retrofit)  ──HTTP──────┼──► Sonarr/Radarr/… (user's servers)
 │ Hive: profiles (connections), lunasea box (tables), logs, indexers    │
 └──────────────▲────────────────────────────────────────────────────────┘
                │ lunasea://<module>?event=…  (ntfy click URL → LunaDeepLinks → module.handleWebhook)
        ntfy server ◄── POST / {topic,title,message,priority,attach,click} ── notification-service
                                                                          ▲
                              *arr webhook → POST /v1/<svc>/<topic> ──────┘
```

The app shows users their webhook URL as `<NOTIFICATIONS_SERVICE_URL>/v1/<module>/<NOTIFICATIONS_TOPIC>`
(`lib/system/webhooks.dart`). Full details: `.agents/docs/architecture.md` and `.agents/docs/notification-service.md`.

## Coding Conventions

### Flutter/Dart

**Files and naming**
- File names are snake_case.
- Each page lives at `routes/<page>/route.dart`, with a `widgets.dart` barrel over `widgets/*.dart`.
- Global and shared classes are prefixed `Luna*`: `LunaProfile`, `LunaBox`, `LunaRouter`, `LunaColours` (British spelling).
- Module classes are prefixed with the module name: `RadarrState`, `TracearrStreamsRoute`.
- Enums are named `<Module>Routes` and `<Module>Database`. Enum values are SCREAMING_CASE, which the lint allows.
- The private state class is named `_State`.

**Imports**
- Use `package:lunasea/...` imports only; relative paths are allowed only inside `export` barrels and conditional platform imports.
- `lib/core.dart` is **deprecated** but still used widely. In new code, prefer direct imports plus `lib/vendor.dart`.

**Settings access**
- Read and write with `XDatabase.KEY.read()` / `.update(v)`.
- Reactive UI uses `XDatabase.KEY.listenableBuilder(...)`, or `LunaBox.lunasea.listenableBuilder(selectItems: [...])`.

**Pages**
- A page is a `StatefulWidget` using `LunaRefreshIndicator` → `FutureBuilder` → `LunaLoader` / `LunaMessage.error` / `LunaListViewBuilder`.
- Log errors with `LunaLogger().error(msg, error, stack)`.

**Strings and platform code**
- User-facing strings use `'<module>.Key'.tr()`. Service names and field labels are sometimes hard-coded in English.
- Platform-specific code uses the conditional import pattern `_stub` / `_io` / `_html`, and callers guard with `isSupported`.
- Documentation comments use dartdoc `///`, mostly in the API libraries. State files use `/// SECTION ///` banners.

Example of a settings table (`lunasea/lib/database/tables/tracearr.dart`):

```dart
enum TracearrDatabase<T> with LunaTableMixin<T> {
  NAVIGATION_INDEX<int>(0), REFRESH_RATE<int>(15), CONTENT_LOAD_LENGTH<int>(50);
  @override LunaTable get table => LunaTable.tracearr;
  @override final T fallback;
  const TracearrDatabase(this.fallback);
}
```

### TypeScript (notification service)

**Formatting (Prettier)**
- Single quotes, semicolons, trailing commas, width 100, 2 spaces.

**Code patterns**
- Imports go through barrel namespaces: `import { Constants, Logger, Notifications } from '../../utils'`.
- Modules follow the `modules/<svc>/{index,controller,models,payloads}.ts` layout.
  - Controllers export `enable(router)` and switch on the event discriminator.
  - Payload functions return a `Notifications.Payload`.
- Logging uses per-module pino child loggers: `Logger.child({ module: 'radarr' })`.
- `any` is allowed for webhook bodies.

### Commits
- Use Conventional Commits, for example `feat(notif): ...`, `fix(android): ...`, `chore: ...`, `ci: ...`, `docs: ...`.
- The app's commitlint allows only `chore`, `docs`, `feat`, `fix`, `refactor` and `release`.

## Development Workflow

flutter pub get

## Common Tasks

1. **Add a new service module.** Follow `.agents/skills/adding-a-module.md`, about 15 files, using Tracearr as the template.
2. **Add a page to a module:**
   1. Create `lib/modules/<m>/routes/<page>/route.dart`.
   2. Add an enum value with a relative path in `lib/router/routes/<m>.dart`.
   3. Add it to the parent's `subroutes`.
   4. Navigate with `<M>Routes.X.go(params: {...}, extra: obj)`, and handle a null `extra`.
3. **Add a setting:**
   1. Add `MY_OPTION<bool>(false)` to `lib/database/tables/<m>.dart`. The storage key becomes `<TABLE>_MY_OPTION`.
   2. Read or write it with `.read()` / `.update()`.
   3. If it stores a custom enum, also give it a new Hive typeId (30+), register the adapter in `register()`, and override `export`/`import`.
4. **Add an API endpoint:**
   - **Retrofit clients** (tracearr, sabnzbd, nzbget): add an annotated method in `api/<m>/api.dart` plus a model, then run `build_runner`.
   - **Radarr / Tautulli:**
     1. Create a new `commands/<group>/<verb>.dart` with `part of radarr_commands;`.
     2. Add it to the `part` list in `commands.dart`.
     3. Expose it on the handler.
   - **Sonarr:** same as Radarr, but in `controllers/`.
5. **Add a translated string:**
   1. Edit `lunasea/localization/<module>/en.json`, adding `"<module>.Key": "..."`.
   2. Run `dart scripts/generate_localization.dart`.
   3. Commit `assets/localization/*.json`.
6. **Add an image asset:**
   1. Drop the file in `lunasea/assets/images/`.
   2. Run `dart pub global activate spider && spider build`.
   3. Commit `lib/widgets/ui/assets.dart`.
7. **Add a webhook event (server side):** add it in 3 places in `lunasea-notification-service/src/modules/<svc>/`: the `models.ts` enum, a `payloads.ts` function, and a controller `case`. Set `data.module`/`event` so the app can deeplink. On the app side, map the event in `lib/modules/<m>/core/webhooks.dart`.
8. **Add a notification-service module:** copy `src/modules/radarr/` and register it in `src/modules/index.ts`. See `.agents/docs/notification-service.md`.
9. **Bump Flutter:** update `FLUTTER_VERSION` in 4 workflows and in `lunasea/Dockerfile`. Re-check the pinned dependencies listed in the `pubspec.yaml` comments.

## Gotchas & Pitfalls

1. **Codegen is mandatory, and its output is not committed.** Fresh clones have no `*.g.dart` files and no `lib/system/environment.dart`. Run the 3 generation steps before `flutter analyze` or any build.
2. **Hive IDs are permanent.**
   - Next typeId: **30**. Next `LunaModule` HiveField: **13**. Next `LunaProfile` HiveField: **48**.
   - Never reuse gaps.
   - Renaming a table enum value or table key resets user settings. The dashboard table key is `'home'`.
3. **Flavor comes from the `FLAVOR` env var at codegen time**, and defaults to `edge`. The `--dart-define=FLAVOR` flags passed by CI and Docker are no-ops.
4. **Only English is enabled** (`supportedLocales: [Locale('en')]`). `generate_localization.dart` wipes and rebuilds `assets/localization/`.
5. **Only root `.github/workflows` run.** The nested `.github` folders in `lunasea/` and `lunasea-notification-service/` are upstream leftovers. **No CI runs on push or PR.**
6. **Upstream leftovers point at other people's infrastructure:**
   - Apple team `VPH33JQH4R`
   - the `JagandeepBrar/fastlane-match-storage` repo
   - `lunasea.app` domains in the iOS associated domains and the Android asset statements
   - the `comettools-lunasea` Firebase project
   - upstream GHCR/OCI labels
   - `downloads.lunasea.app` in `generate_changelog.dart`

   iOS and macOS CI builds are therefore unsigned.
7. **Android CI signing.** Without the four `ANDROID_KEYSTORE_*` secrets, CI signs every build with a new ephemeral key, so APKs cannot upgrade over each other. Never commit `*.jks`, `*.keystore` or `key.properties`.
8. **TLS certificate validation is off by default** (`NETWORKING_TLS_VALIDATION=false`) on IO platforms.
9. **Overseerr and Wake-on-LAN are partial modules:**
   - `LunaModule.OVERSEERR` exists, but `featureFlag` is false and there is no UI; it is notifications only.
   - WAKE_ON_LAN has no route, and `shortcutItem` throws for it.
10. **Web limits:**
    - Wasm needs the COOP/COEP headers from `nginx/default.conf`.
    - go_router `extra` is lost on refresh.
    - Deep links, quick actions, the window manager and the image cache are unsupported.
11. **The notification service responds 200 before processing**, so failures are only visible in its logs.
    - A missing JSON body throws inside the handler.
    - The root compose healthcheck for `notifications` uses `wget`, which the distroless image lacks, so it always reports unhealthy.
12. **The notification service has no Tracearr module**, although the app does.
13. **`provider` is not declared in `pubspec.yaml`.** It works only as a transitive dependency.
    Keep `pubspec.lock` in sync: after any `pubspec.yaml` change, run `flutter pub get` and commit the lockfile.
14. **Pinned dependencies:**
    - `file_picker ^12.0.0-beta.4`. In the new static API, `saveFile(bytes:)` writes the file itself.
    - `xml ^6`
    - `hive_ce_generator ^1.11.1`, pinned because of Flutter 3.41's `meta 1.17`.
15. **Docker release tags must be semver**, or no image tags are produced. Trivy never fails the build.
16. **The docs site is Jekyll, not GitBook.** Its content still references upstream download sites and the `ghcr.io/jagandeepbrar/lunasea:stable` image on port 80. This fork's image is `ghcr.io/<owner>/lunasea/lunasea-web` on port 8080.
17. **Shallow clones:** cloud checkouts may be shallow, so do not depend on `git rev-list --count`.
